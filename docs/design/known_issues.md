### 프로세스: Bash 툴에서 멀티라인 커밋 메시지에 `@'...'@`(PowerShell here-string) 쓰면 `@` 가 섞인다
- **증상**: `git commit -m @'...'@` 를 Bash 툴로 실행하니 커밋 제목 첫 줄이 `@`, 마지막 줄도 `@` 가 됐다.
- **원인**: `@'...'@` 는 PowerShell 전용 here-string. POSIX sh(Bash 툴)에선 `@` + 작은따옴표 문자열 + `@`
  로 해석돼 리터럴 `@` 가 앞뒤로 붙는다(Bash 툴 설명에도 "PowerShell here-string 쓰지 말 것" 명시).
- **재발 방지**: Bash 툴에서 멀티라인 메시지는 **파일로 써서 `git commit -F <파일>`**(또는 heredoc).
  `@'...'@` 는 PowerShell 툴에서만 쓴다. (이번엔 `git commit --amend -F` 로 메시지 교정.)

### 프로세스(기법): 동시 세션과 한 파일이 섞였을 때 내 hunk 만 선택 스테이징
- **상황**: 내 변경(주석)이 다른 세션의 미커밋 변경과 같은 파일(game-ui.ts)에 공존. `git add <파일>` 하면
  그 세션 변경까지 커밋된다(동시 세션 루틴 위반). 대화형 `git add -p` 는 이 환경에서 막혀 있다.
- **해결**: `git diff <파일> | awk '/^@@ -<다른세션hunk시작줄>/{stop=1} !stop{print}' > my.patch` 로 내 hunk
  만 추린 뒤 `git apply --cached my.patch`. 그 파일의 다른 세션 hunk 는 작업트리에 그대로 남아 커밋에서 제외된다.

### AI: 막다른 위치(빈 칸이 전부 상대 잠긴 벌집 + 타일 소진)에서 불법수 반환
- **증상**: 자가대국 시뮬레이션 장기전에서 applyMove 가 "이번 턴에는 타일 1개 + 말 1개를
  할 수 없습니다" throw. fallbackMove 가 검증 안 된 tileAndPiece 를 반환.
- **원인**: 타일 소진(tiles=0) + 빈 칸이 전부 상대 잠긴 벌집이면 일반 말로는 둘 곳이 없다.
  그런데 엔진 canMove 는 "여왕벌로 둘 수 있다"고 판단해 게임을 안 끝내고 그 플레이어를 턴에
  올린다. AI 는 여왕벌을 안 써서 정규 후보가 0개 → fallbackMove 가 최후에 미검증 수를 반환.
- **재발 방지**: fallbackMove 가 막다른 경우 **여왕벌을 최후 수단으로** 둬 합법수 계약을 지킨다
  (정규 전략 아님, 정지/불법수 방지용). 회귀 테스트: "막다른 위치에서 여왕벌 최후 수단".
  교훈: canMove 의 "둘 수 있다" 정의(여왕벌 포함)와 AI 후보 생성(여왕벌 제외)이 어긋나면
  데드락이 생긴다. self-play 장기전이 이런 엣지를 잘 드러낸다.

### AI: 잠긴 벌집 승리 칸 오판으로 vs AI 가 "생각 중"에서 영구 정지
- **증상**: vs AI/관전에서 갈색 "리치! 여기 두면 승리"인데 AI가 못 두고 "생각 중"에서 멈춤.
- **원인**: `winningCells` 는 `supply.queenUsed=false` 면 잠긴 상대 벌집 칸도 **여왕벌 가능성**으로
  승리 칸에 포함한다. AI 는 여왕벌을 안 써 그 칸에 normal 말을 두려다 `applyMove` 가 throw →
  game-ui 의 setTimeout catch 가 복구 없이 render 만 해 영구 정지. `ai.ts` 의 "항상 합법수 반환"
  계약을 placementMove 가 미검증 수로 어긴 것이 근본.
- **재발 방지**: 승리/차단용 수 생성기(placementMove)는 **반드시 validateMove 통과 수만** 반환.
  UI 의 리치 표시는 모드(여왕벌 ON/OFF)를 반영해 호출(OFF면 queenUsed=true 사본). AI 수는
  적용 전 한 번 더 validateMove(방어). 관련 회귀 테스트: "잠긴 벌집 승리 칸" 케이스.

### 검증: fill="none" SVG 폴리곤은 내부 클릭이 아래로 통과 → Playwright 가 거부
- **증상**: verify/shot 스크립트가 초록 타깃 링(`stroke=#16a34a`) 클릭에서 무한 재시도 후
  타임아웃("...intercepts pointer events", 아래 타일 폴리곤이 가로챔).
- **원인**: 타깃/프론티어 링은 `fill="none"` 이라 내부 픽셀이 포인터를 안 받음 → 실게임은
  같은 칸 타일(onClick 보유)이 대신 받아 정상이지만, Playwright 액셔너빌리티 검사는
  "그 요소가 최상단이 아님"으로 클릭을 거부한다.
- **재발 방지**: verify/shot 에서 링·프론티어 클릭은 `.click({ force: true })` 로(아래 타일이
  핸들러를 가지므로 동작은 동일). happy-dom 단위 테스트는 히트테스트를 안 해 못 잡는다.

### 모바일: 페이지(루트) 스크롤로 fixed 오버레이(온보딩) 어긋남
- **증상**: 모바일에서 화면이 실제 뷰포트보다 커져 페이지가 세로로 스크롤되고, `position:fixed`+
  `getBoundingClientRect` 로 위치를 잡는 앱 온보딩(스포트라이트) 콜아웃/구멍이 어긋나 보임.
- **원인**: `#app`/`.game` 은 `100dvh` 로 맞췄지만 루트(html/body)에 스크롤 차단이 없어, 주소창
  노출/숨김·바운스·`dvh` 갱신 타이밍에 따라 루트가 스크롤됨. Playwright 에뮬레이션은 이 동적
  뷰포트 변화를 재현하지 않아(docScrollH==innerH) 정적 분석으로는 안 보임.
- **재발 방지**: 루트 스크롤은 **명시적으로 잠근다** — `html, body, #app { overflow:hidden;
  overscroll-behavior:none }` + 높이 고정. 스크롤이 필요한 곳만 자체 스크롤 컨테이너로:
  설정 시트(`.panel`)는 `overflow-y` + `overscroll-behavior:contain`, 보드는 JS pan(`touch-action:none`).
  화면이 100dvh 안에 들어오게 flex(보드 `flex:1; min-height:0`)로 짜면 잠가도 클리핑되지 않는다.
- **후속(중요)**: `overflow:hidden` 만으론 비스크롤 영역(상단 HUD 등) 드래그로 페이지가 움직이고
  주소창이 끌려 올라간다. 해법은 **비스크롤 영역에 `touch-action:none`** — `.board-wrap`(보드·HUD·
  안내·행동바)·`.m-fab` 에 주면 드래그를 네이티브 스크롤로 해석하지 않는다(보드 팬은 JS pointer 라
  유지). **주의1**: `touch-action:none` 을 설정 시트의 **공통 조상**(`body`/`#app`/`.game`)에 주면
  시트 내부 스크롤까지 막힌다(touch-action 은 조상과 교집합) → 시트 **밖** 요소에만 준다.
- **함정(겪음)**: 끌림을 막으려 **`body { position:fixed; inset:0 }`** 를 쓰면 `#app` 의 `100dvh` 와
  어긋나 **실기기에서 화면 비율이 깨진다**(갤럭시 S22+ 확인). position:fixed 로 풀지 말 것 —
  `touch-action:none` + `overflow/overscroll` 로 충분하고, 화면 크기는 `#app{100dvh}` 단일 기준 유지.

### 온보딩(스포트라이트): 콜아웃 문장 중간 줄바꿈 + 패널 스크롤 시 단계가 화면 밖
- **증상**: ① 콜아웃 설명이 한 문장을 화면 폭에 못 담아 문장 중간에서 줄바꿈돼 가독성↓. ② 설정 패널을
  쭉 내린 뒤 "앱 사용법 다시 보기"로 재오픈하면 패널을 가리키는 단계(모드·난이도 등)가 화면 밖에 그려짐.
- **원인**: ① 콜아웃 폭(min(94vw,26rem))보다 긴 문장이 자동 줄바꿈. ② 대상(`[data-act=menuMode]` 등)이
  스크롤된 패널 밖에 있어 `getBoundingClientRect`가 화면 밖 좌표를 반환 → 스포트라이트·콜아웃이 거기 그려짐.
- **재발 방지**: ① **본문 줄바꿈은 `<br>`로 문장(구) 단위만** — 한 구간 한글 ~18자 이내(콜아웃 폭 안).
  추가/수정 시 단계별 `.coach-body` 높이 = (`<br>`수+1)×lineHeight 인지 점검(불일치=중간 줄바꿈).
  ② 단계 진입 시 대상을 **`scrollIntoView({block:'center'})`** 로 보이게(루트 스크롤은 잠겨 있어 패널만
  움직임). 비슷한 rect 기반 배치(미래)도 같은 함정 — 대상이 스크롤 컨테이너 안이면 먼저 스크롤.

### 멀티플레이: 방 코드를 여럿에게 뿌려 3명+ 동시 접속 시 desync(만석 처리 누락)
- **증상**: 초대 코드/링크를 단톡방 등에 뿌려 3번째 사람이 들어오면, 그 사람이 게스트 진영으로 입장해
  실제 게스트와 같은 색을 동시에 조작 → 스냅샷이 서로 덮어써 두 플레이어 모두 desync.
- **원인**: ① `joinOnline` 이 만석(이미 host+guest 차고 내가 그중 하나가 아님)을 검사하지 않고 무조건
  게스트로 enterOnline. ② `joinRoom` 의 슬롯 차지가 비원자적(`.is('guest_id', null)` 없이 update)이라
  동시 입장 레이스에서 둘 다 슬롯을 얻을 수 있었음.
- **재발 방지**: ① `joinOnline` 에 만석 가드 — `host_id!==me && guest_id!==me && guest_id!=null` 면 입장
  거절(메시지+해시 정리). ② `joinRoom` 슬롯 차지를 `.is('guest_id', null)` 원자적 update + `maybeSingle`,
  0행이면(그 찰나 누가 차지) 방을 다시 읽어 반환 → 호출 측이 만석으로 거절. 방은 2인 전용(관전 미지원).
