# 2026-06-23 세션 로그

> 자정을 넘겨 이어진 한 세션(시작은 06-22 밤). 비주얼 반복 + 전문가 AI 신설.

## 요약
말/타일 비주얼을 실물 사진에 맞춰 여러 번 고치고(2.5D 디스크 → 롤백 → 귀여운 SVG 벌 →
three.js 3D 벌), hard 위 **전문가 난이도 + 결정적 수 해설**을 신설했다. 전문가는 두 번 회귀를
겪고 빔12·깊이4 + gapped-four 로 확정(hard에 2-0-2 무패).

## 주요 변경
- **비주얼(SVG)**: 디스크/타일두께 재설계가 가시성을 해쳐 **롤백** → 진영색 둥근 배 + 큰 흰 눈·검은
  머리·날개·줄무늬의 **귀여운 꿀벌**(반쯤 박힌 느낌, 떠있는 그림자 제거). `game-ui.ts`.
- **three.js 데모(`public/three-demo.html`)**: 사용자 피드백 반복 반영 — 디스크/더듬이/돌출 눈 제거
  → 매끈 몸통 + 색칠한 무늬·눈 → 최종 **LatheGeometry 길쭉한 회전체**(배→허리 잘록→머리), 눕혀
  납작하게, 텍스처로 줄무늬·머리·눈 색칠(눈은 눕힌 회전체의 위쪽 u≈0.75 에 배치).
- **전문가 AI(`ai.ts`)**: `Difficulty='expert'`, `gappedFours()`(벌어진 4목 탐지), `evaluate` gapFour 항,
  `analyzeMove()`(win/fork/block/corridor 분류). UI: 난이도 메뉴 노출 + `.ai-comment` 해설 말풍선.
- **검증 스크립트**: `scripts/verify-expert.mjs`(메뉴 노출 + 응수 + 에러 0).
- **문서**: `ai_strategy.md` 전문가 설계·튜닝 일지, `backlog.md` 갱신.

## 결정 사항
- **비주얼 shipping = SVG 귀여운 벌.** 디스크/3D 토큰은 가시성·실물감 모두 손해라 롤백. 진영색은
  벌 몸 색으로(둘 다 노란 벌+베이스 안 함, 사용자 선택).
- **3D 절차적 모델은 한계.** 회전체로 형태는 맞췄지만 절차적 프리미티브로 실물 "귀여움"을 완전히
  살리긴 어렵다. 진짜 3D 모드를 하려면 **Blender GLTF 자산**이 정도(데모는 three.js 가능성 시연용).
- **전문가 강함 = 넓은 빔 + gapped-four**(깊이 5·6은 한 수 수~수십 초라 폭발). `hiveDef`·좁은 빔은
  독(각각 0-8, 0-4 회귀로 확인). 금수 룰은 안 넣음(선후공 유불리 작음).
- **전문가 해설**은 `winningCells` 기반이라 가짜 위협을 안 잡고, 전문가 난이도에서만 표시.

## 세션 2 — 엎드린 탑다운 벌 구현(backlog #1 완료, SVG+3D)

### 요약
직전에 정정한 방향("타일에 배를 대고 엎드린, 위에서 내려다본 벌")대로 **SVG 게임 말**과
**3D 데모 벌**을 모두 탑다운으로 재작성했다. 깨져 있던 `verify:click`(튜토리얼 미스킵)도 고쳤다.

### 주요 변경
- **SVG 말(`src/ui/game-ui.ts`)**: 둥근 "귀여운 벌"(큰 눈) → **탑다운 벌**로 교체. 구성: 검은 머리
  (작은 눈+짧은 더듬이) → 둥근 가슴 → **길쭉한 타원 배에 검정 줄무늬 3줄**(타원 현 폭에 맞춰 또렷),
  **등 위로 흰 날개 2장**(±62° 펼침, 가운데 줄무늬는 안 가림). 진영색=배 바탕(`bee-${owner}` 그라디언트),
  줄무늬=테마 `piece.stripe`(그동안 미사용이던 값). **`circle.piece` 계약 유지**: 테스트/verify가
  `circle.piece`를 세므로 배(ellipse) 대신 **둥근 가슴을 circle.piece**로 삼음.
- **3D 데모(`public/three-demo.html`)**: 옆으로 누운 LatheGeometry 회전체 → **탑다운 조립**. 배를
  납작 구체 마디 5개(노랑/검정 교대=줄무늬, 뒤로 갈수록 가늘게)로, 가슴·검은 머리·작은 눈·더듬이·
  **등 위 납작 흰 날개**. 텍스처/회전체 제거(`beeTexture`/`beeProfile`/Lathe 삭제). 카메라 각도도
  살짝 위로(탑다운이 잘 보이게).
- **`scripts/verify-click.mjs`**: 튜토리얼 오버레이 스킵(`tutorial-seen=1` + reload) 추가 → 다시 PASS.

### 결정 사항
- **메인 몸통은 반드시 `<circle class="piece">`**(테스트·9개 verify 스크립트가 `circle.piece`를 셈).
  길쭉한 배는 ellipse라 못 셈 → 가슴 circle을 piece로. 배·머리·날개는 비계측 요소.
- **줄무늬 색은 테마 `piece.stripe` 사용**(기존엔 하드코딩만 함). 진영별로 어두운 톤이 다름.
- **3D 데모는 절차적 한계 그대로**(known_issues). 방향만 바로잡았고 캐릭터 완성도는 SVG가 더 높다.
  3D 본체 정식 전환은 여전히 사용자 결정 대기(backlog #2).

### 미해결 / 다음 할 일
- **사용자 확인**: 새 탑다운 벌(SVG/3D) 모양 OK인지. 미세 조정 여지(눈 크기, 날개 각도, 갈색벌 줄무늬
  대비). 갈색 진영은 배가 어두워 줄무늬 대비가 약함 — 필요하면 갈색벌 줄무늬를 더 밝/어둡게.
- backlog #2(3D 본체 도입 여부) = 사용자 결정. 그 외 폴리시·AI 튜닝은 선택.

## 세션 3 — 말 = 원판 + 벌(실물 토큰 그대로) 재작업

### 요약
세션 2의 "벌 그림만"은 틀렸다. 사용자가 실물 사진으로 정정: **말 = 육각 타일 위 고동색 원판 +
그 위에 칠한 벌**이 한 세트("원판까지가 말"). 펼친 날개도 틀림 — 실물 벌은 몸에 **넓은 흰 띠**다.
SVG·3D 데모를 모두 원판+벌로 다시 만들고, 두 진영이 원판 위에서 구분되도록 벌 색을 정리했다.

### 주요 변경
- **SVG 말(`game-ui.ts`)**: 탑다운 날개벌 → **고동색 원판(circle.piece) + 벌**. 벌 = 검은 머리(흰 눈 2개)
  → 노란/주황 몸에 **검정 줄무늬 + 넓은 흰 띠** → 어두운 꼬리(레퍼런스 그대로, 날개 없음). 원판엔 옅은
  그림자·옆면 두께·광택으로 "떠 있는 토큰" 느낌. `circle.piece`는 이제 **원판**(테스트/verify 계약 유지).
- **진영 구분 = 벌 색**: 원판은 모든 타일색과 대비돼야 해 **둘 다 고동색** 고정(밝은 원판은 갈색 타일에
  묻힘) → 노랑 진영=노란 벌(#f4b40a), 갈색 진영=**주황 벌**(#e8771a). 둘 다 고동 원판 위에서 또렷·구별됨.
- **3D 데모(`three-demo.html`)**: 마디 벌 → **원판 실린더 + 벌**(마디에 흰 띠 추가, 날개·더듬이 제거,
  머리 검정·흰 눈). BODY 색도 노랑/주황으로 통일.

### 결정 사항
- **말은 원판+벌 한 세트**(과거 원판 롤백을 "원판 자체가 나쁘다"로 오독했던 것을 바로잡음 — known_issues).
- **원판=고동색 고정, 진영=벌 색**. 원판색으로 진영을 나누면 밝은 원판이 갈색 타일에 묻혀 불가.
- 벌은 **흰 띠**(날개 아님). 레퍼런스 사진이 단일 진실.

### 미해결 / 다음 할 일
- **사용자 확인**: 원판+벌(노랑/주황) 방향 OK인지, 주황 진영색·원판 톤·흰 띠 위치 미세조정 필요한지.
- backlog #2(3D 본체 도입 여부) = 사용자 결정.

## 세션 4 — 전체 보드게임 사진 반영(진영=원판색) + 3D 두 버전

### 요약
실물 보드게임 전체 사진을 받음. 핵심 정정 둘: ① **진영 구분은 원판 색**(노란 원판 / 갈색 원판)이고
**벌은 양쪽 다 같은 노란 벌**(세션 3의 "주황 벌"은 틀림). ② 벌의 흰 부분은 **접힌 날개**이지 펼친
날개가 아님. SVG를 그에 맞게 고치고, 3D는 사용자 지시대로 **두 버전**(스타일 회전체 2개 / 현실 벌)을 만듦.

### 주요 변경
- **SVG 말(`game-ui.ts`)**: 진영=원판색(노란 #d8a92b / 갈색 #743f30), **벌은 공통 노란 벌**.
  날개=일자 선 → **둥근 접힌 흰 날개 2장**(등 가운데), 줄무늬는 날개 위·아래로 안 가리게(머리 아래 1줄 +
  배 아래 2줄). **더듬이 짧게(뽀짝) + 끝 동그라미**. 원판은 같은 색 타일에서도 그림자+옆면+테두리로 분리.
- **3D 스타일 버전(`three-demo.html`)**: 사용자 지시 — **회전체 단 2개(머리 구 + 몸통 Lathe)**,
  몸통 줄무늬는 **표면 텍스처로 색칠**(마디 블롭 전부 제거). 원판 위, 진영=원판색.
- **3D 현실 버전(신규 `three-demo-real.html`)**: 머리(겹눈·더듬이)+털가슴+줄무늬 배(뾰족 꼬리)+
  반투명 날개 2쌍+다리 6개. 두 데모는 상단 nav 로 서로 전환.

### 결정 사항
- **진영 = 원판 색**(노란 원판 / 갈색 원판), **벌은 공통 노란 벌**. 실물 보드게임 그대로 — 단일 진실은 사진.
- 벌의 흰 부분 = **접힌 날개**(rounded), 펼친 날개·일자 선 아님. 줄무늬를 가리면 안 됨.
- **3D 스타일은 회전체 2개 + 표면 색칠**이 정답(마디 블롭 쌓기 = "찰흙 무더기"). 현실 벌은 별도 옵션으로 둘 다 제공.

### 3D 미세조정(이어서)
- **현실 벌 날개**: 배 위에 떠 있던 것 → **뿌리를 가슴(앞)에 모으고 꼬리로 갈수록 바깥으로 퍼지게**
  (root→tip 벡터로 quaternion 정렬한 `wing()` 헬퍼). `three-demo-real.html`.
- **스타일 벌**: 몸통이 납작해 입체감이 없던 것 → 높이 스케일 ↑(돔처럼 솟게). 눈이 파묻힌 것 →
  머리 윗면 위로 또렷한 흰 점(거의 위를 보게). `three-demo.html`.
- **SVG는 손대지 않음** — 사용자가 Claude Design에서 직접 새로 작업 중(대기).

### 미해결 / 다음 할 일
- **사용자 선택**: 3D 스타일(①) vs 현실(②) 중 어느 방향을 (만약 3D 도입 시) 쓸지.
- backlog #2(3D 본체 도입 여부) = 사용자 결정.

## 세션 5 — SVG 핸드오프 이식 + 현실 벌 마감

### 요약
사용자가 Claude Design 에서 만든 SVG 말 디자인을 `design_handoff_bee_pieces/`(hifi 스펙)으로
전달 → `game-ui.ts` 말 렌더를 그 스펙으로 통째 교체. 현실 3D 벌은 날개 1쌍·다리 접지·원판 추가로 마감.

### 주요 변경
- **SVG 말(`game-ui.ts`)**: 핸드오프 스펙(viewBox 0~200, 원판중심 100,100·반지름 80) 이식.
  각 말을 그룹 transform 으로 셀 좌표(반지름 `DISC_R = HEX_SIZE*0.6`)에 매핑. 원판 그라디언트
  (gold/brown)·옆면·림·광택 + 벌(더듬이·몸통 그라디언트·**몸통 타원에 클립한 줄무늬·꼬리**·날개 ±40°·
  머리·눈) + 여왕벌(빨간 링 r71 + 왕관). `circle.piece`=원판 윗면. 셀 해시 tilt(±18°).
  공유 `clipPath`(userSpaceOnUse)가 변환 그룹 안에서 셀별 정렬됨.
- **`design_handoff_bee_pieces/`**: 디자인 단일 출처로 함께 커밋(SVG 4종 + 컴포넌트 + README).
- **현실 3D(`three-demo-real.html`)**: ① 파묻힌 뒷날개 제거(날개 1쌍), ② 다리를 원판 윗면(y=0.36)에
  닿게(몸은 원판 위로 떠서 다리로 섬, Y=0.64), ③ 진영색 원판 추가(말=원판+벌, 색 구분).

### 결정 사항
- **SVG 말 = 핸드오프 스펙이 단일 출처**. 절차적 손그림 대신 디자인 산출물을 그대로 이식.
- 줄무늬는 몸통 타원 clipPath 로 — 끊김 없이 가장자리까지, 꼬리는 통검정으로 이어짐.
- 현실 벌도 **원판 위에 선다**(색 구분). 스타일/현실 둘 다 원판 토큰으로 통일.

### 미해결 / 다음 할 일

## 세션 6 — SVG 원판 접지 정렬 + 3D 마감(스타일=SVG돔, 벌 축소)

  (노랑 + 검정 2줄 + 검정 꼬리, 흰띠 제거), 몸통을 도톰한 돔으로, **흰 날개 2장**(svg처럼 옆으로 펼침)

## 세션 7 — AI 평가 최적화(전문가 응답속도)

### 요약
SVG 디자인 외주 대기 중, 비주얼과 무관한 `evaluate` 성능 최적화를 진행. 노드마다 보드를 6~9회
풀스캔하던 것을 **1회 스캔 + findLines 공유**로 바꿔 전문가 한 수를 ~5.95초 → ~4.8초(31칸 보드
기준 **약 19% 단축**, 후반 큰 보드일수록 더 큼)로 줄였다. **수 선택·평가값은 byte-identical**.

### 주요 변경(`src/engine/ai.ts`)
- `evaluate` 가 보드를 **단 1회** 훑어 ownerPieceMap(me/opp)·ownerTileMap(me/opp)·말 위치(me/opp)·
  선점(seize) 점수를 동시에 모은다. `findLines` 는 맵당 1회만(피스선·타일선) 구해 헬퍼에 넘긴다.
- 헬퍼(`sideStats`·`contestBonus`·`tileDevScore`·`imminentHives`·`gappedFours`·`centralityPenalty`)는
  보드 대신 **사전계산 선/말위치**를 받는 시그니처로. `hiveContestTerm`·`seizeScore`·`ownerPieceMap` 제거.
- `totalHiveScores(board)`(detectHives 풀스캔)도 제거 — 벌집 = 같은 색 타일 5+ 런이므로 이미 만든
  `tileLines` 에서 `len≥5 → len−4` 합산으로 동일 계산(풀스캔 1회 + findLines 1회 추가 절감).

### 결정 사항
- **순수 리팩터(동작 불변)**: findLines 는 최대 run+minLen 필터라 1회 계산해 필터링하면 동일. 맵 삽입
  순서·합산 순서가 같아 평가값이 byte-identical. → 가중치 변경이 아니므로 self-play 불필요(known_issues
  의 "가중치/탐색 변경 시 self-play" 대상 아님). 단위 테스트 74개 + A/B 동일 수 선택으로 검증.
