# 2026-06-29 세션 로그

## 요약
AI 강화: 2026-06-29에 발견된 "잠긴 회랑 양방향 맹점"의 **공격 절반**을 수정했다. 전문가 AI가
자기 벌집을 잠가 상대가 막을 수 없는 말 5목을 노리는 `lockedRun` 평가 항 + 루트 잠금-시딩을
추가. 합성 위치로 효과를 확인하고 필드 self-play(vs hard)로 약화 없음을 검증했다.

## 주요 변경
- `src/engine/ai.ts`:
  - `Weights.lockedRun` 신설(기본 0, `EXPERT_WEIGHTS` 에서 10000). 잠긴 벌집 안 "막을 수 없는
    5목"까지 남은 수(`hiveCountdowns` 재사용)를 movesLeft별로 반대칭 보상하는 평가 항.
  - `lockingMoves()` 신설 + `searchBestMove` 루트에서 시딩(전문가 전용, `lockedRun!==0` 게이트).
    내 타일선(길이 3·4)을 연장해 5타일 벌집으로 잠그는 ①/②수를 루트에 강제로 끼운다. **창에 내
    말 ≥1·상대 말 0일 때만** 시드(타일 쫓기 회피). 루트에서만(빔 폭발 방지).
- `tests/ai-lockedrun.test.ts` 신설: 합성 위치(갈색이 회랑을 잠그면 막을 수 없는 movesLeft=2).
  ON이면 잠그고 OFF(lockedRun=0)면 못 잠그는 것을 단정 → 이 항이 원인임을 고정. 전문가 it에
  타임아웃 부여(60000/30000).
- 문서: `ai_strategy.md`(lockedRun 절), `ai_hive_lock_defense.md`(공격 절반 해결 갱신),
  `known_issues.md`(시딩 교훈), `backlog.md`(#2 트림).

## 결정 사항
- **왜 공격 절반부터인가**: 실패한 세 시도(2026-06-27 평가, 2026-06-28 규칙, 그리고 공격 배율)는
  모두 **방어/예방**(잠기기 전 끊기)이라 보상이 10수+ 뒤 → depth-4 지평 밖이라 못 잡혔다. 반면
  **공격**(이미 잠긴/곧 잠길 회랑 활용)은 승리가 "잠금→채움→채움"(depth-5)으로 지평을 **막**
  벗어날 뿐이라, 잠근 직후 국면의 leaf 평가에 `hiveCountdowns` 가치를 보이게 하면 탐색이 잠금수를
  고른다. 본질적으로 더 다루기 쉬운 표적.
- **평가 항만으론 부족했다**: `lockedRun` 평가만 넣었을 땐 여전히 안 잠갔다 — 후보 생성기가
  "내 타일선을 연장해 잠그는 ②수"를 잘 안 만들어 그 수가 후보에 없었기 때문. `findBlock`/방어수
  처럼 **루트 시딩**으로 보강해야 비로소 잠근다.
- **타일 쫓기 회피 근거**: lockedRun 은 **이미 잠긴 벌집 + 그 안 내 말**에만 작동하고(빈 벌집·
  미잠금엔 0), 시딩도 **창에 내 말이 이미 있을 때만** 한다. 빈 벌집을 처음부터 좇게 만들지 않는다.
- **self-play 결과(N=2, 8판)**: ON(lockedRun=10000) vs hard = 4승 0패, OFF(0) vs hard = 2승 2무.
  ON이 무를 승으로 바꿔 오히려 더 결정적(잠긴 회랑으로 마무리). 약화 없음 → 채택. 시간도 ON이
  더 빨랐다(637s vs 752s, 빨리 끝나서). 표본은 작아 stark 회귀만 잡는 수준임을 명시.

## 미해결 / 다음 할 일
- **방어 절반(prevention)은 여전히 미해결**: 회랑이 잠기기 **전에** 끊는 것은 보상이 10수+ 뒤라
  depth-4로 못 본다(MCTS/학습 재설계 영역). backlog #2 의 사람-회랑 패배(게임1~3)는 이 방어
  문제라 lockedRun 으로 직접 풀리지 않는다. 다만 AI 가 공격적으로 자기 회랑을 만들면 상대가 응수
  하느라 회랑을 못 쌓는 **간접 효과**는 기대 가능(주도권 강화, ai_hive_lock_defense §5 #2).
- lockedRun magnitude(movesLeft별 9/3/1/0.4 × 10000)는 N=2 검증치 — 큰 표본(`LR_N` ↑)으로
  방어-공격 균형을 재확인하면 더 정밀. 약화 신호 시 movesLeft=3/4 값을 낮추는 게 1순위.

## 세션 2 (MCTS 엔진 — 방어 절반 돌파)

### 요약
잠긴 회랑 문제의 **방어/예방 절반**(잠기기 전 끊기 — depth-4 지평 밖이라 expert 가 못 함)을 노려
MCTS 엔진을 만들었다. 휴리스틱+MCTS-Solver 방식(엔진 재사용)이 **expert 를 10승 2패로 압도**하고,
사람-회랑 기보(게임1·2)의 결정적 순간에 회랑을 **예방**한다(expert 는 못 하는 수). 학습 네트워크
없이 풀려 문서의 비관적 전망("MCTS/학습 재설계 필요")보다 좋은 결과.

### 주요 변경
- `src/engine/ai.ts`: MCTS 엔진 추가(`engine:'mcts'`·`mctsSims` 옵션, 기본 OFF — 기존 AI 무영향).
  - UCT 선택 + **MCTS-Solver**(종료 확정값 역전파) + 전술 단축(즉시승/차단) + 잠금 시딩 +
    랜덤(ε=0.4) 섞인 휴리스틱 롤아웃(depth 5). 값은 노랑 관점 [-1,1](tanh(evaluate/80000)).
  - 엔진(applyMove/evaluate/generateCandidates/lockingMoves/defensiveMoves) 전부 재사용.
- `tests/ai-mcts.test.ts`: 합법 플레이 + 공격(잠그기) + **예방**(게임1 4수 회랑 선점) 회귀. it 타임아웃.

### 결정 사항
- **왜 MCTS 가 방어를 푸나**: expert(depth-4)는 회랑 잠김→악용이 지평 밖이라 못 본다. MCTS 는
  ① 선택적 심화로 그 라인까지 닿고, ② **Solver** 가 그 끝의 확정 결과(잠긴 회랑 = 확정승/패)를
  역전파하며, ③ ε-랜덤 롤아웃이 회랑 형성을 가끔 드러낸다 → "안 끊으면 진다"가 값에 잡혀 끊는다.
- **휴리스틱 재사용이 핵심**: 순수 랜덤 롤아웃은 이 게임(고분기·장기전)에서 약하다. 잘 튜닝된
  `evaluate` 를 leaf/롤아웃 값으로 써서 전략적 기반을 줬고, Solver 로 전술 정확도를 보강했다.
  덕분에 학습 네트워크 없이 expert 를 이긴다.
- **검증(self-play, vs expert, 양 진영)**: 4판 4-0 → 확인 8판 6-2 = **누계 10승 2패(12판, ~83%)**.
  2패는 모두 MCTS 가 갈색(후공·방어)일 때 — 완벽하진 않지만 분명히 더 강하다. 예방은 게임1 4수
  (-1,1)·게임2 8수 (2,1) 회랑 선점으로 확인(expert 는 둘 다 회랑 밖).
- **속도**: ~5~6s/수(sims=800, 일정). expert 는 후반 2~30s 로 들쭉날쭉 → MCTS 가 오히려 고를 수도.
- **기본 OFF 유지**: `engine:'mcts'` 실험 플래그 뒤에 둬 기존 AI/UI 무영향. UI 노출(새 티어 vs
  expert 교체)은 사용자 결정 사항(속도 트레이드오프).

### 추가 검증(사용자 "먼저 더 검증" 요청) — 핵심: 강하지만 느리다
- **강도(vs expert, sims=800, 양 진영 누계)**: 4-0 + 6-2 + 5-1 = **15승 3패(18판, ~83%)**. 확실히 강함.
- **sims 트레이드오프(각 6판)**: sims=800 → **5승 1패**, sims=400 → **2승 4패(진다)**. 강함이 곧 sim
  수에서 나온다 → **sims 를 낮춰 빠르게 하면 expert 보다 약해진다**. "빠르면서 강한" 지점이 없다.
- **속도(정정, 중요)**: 열린 국면 **median ~11s/수**(이전 "~5s" 는 짧게 끝난 판 평균이라 과소). 게임
  평균도 sims 400/800 모두 **~10~11s/수**. UI 기본 엔진엔 너무 느리다.
- **예방 일반화 한계**: 게임1(s=0)·게임2(대각선) 같은 **이른·짧은 지평** 회랑은 선점하지만, 게임3
  (q=4 회랑, 20수+에 걸쳐 형성)은 32·36수 모두 **못 막았다**. 지평이 멀면 MCTS 도 한계.
- **결론**: 강함의 블로커는 **속도(롤아웃 비용 ~13ms/sim)**. UI 노출 전 **롤아웃/평가 최적화**(sim 당
  비용↓)로 같은 강도를 ~2~3s/수에 내야 쓸 만하다. 그 전엔 실험 플래그(`engine:'mcts'`, 기본 OFF) 유지.

### 미해결 / 다음 할 일
- **(블로커) MCTS 성능 최적화**: 롤아웃 비용을 낮춰(가벼운 플레이아웃 정책·깊이↓·후보생성 캐싱) 같은
  강도를 ~2~3s/수에. 이게 UI 노출의 전제. (시간예산 캡은 sim 수를 깎아 약화되니 답 아님 — 400 이 이미 짐.)
- **UI 노출 방식**: 최적화로 빨라지면 (a) 새 "최고난도" 티어 vs (b) expert 교체 결정. 지금은 (c) 실험 유지.
- 게임3류 **긴 회랑 예방** + 갈색 후공 패인은 별도 과제(지평이 멀어 MCTS 도 부분적).

## 세션 3 (MCTS 최적화) — 트리 6~7배↑, 강함은 롤아웃에 묶임

### 요약
MCTS 속도 최적화. 프로파일로 두 병목을 찾아 **확장 비용을 6~7배 줄였고**(노드별 evaluate 재정렬
제거), 롤아웃 비용을 줄이는 여러 시도를 측정했다. 결론: **dominance(15-3)는 비싼 정확한 롤아웃에
본질적으로 묶여 있다** — 롤아웃을 줄이면 빠르지만(~1s) expert 와 비등(회랑 예방은 유지). "빠르고
강한" 지점은 학습 가치함수 없이는 없다.

### 주요 변경 (`src/engine/ai.ts`)
- **`mctsActions` 에서 노드별 `evaluate×후보(~18)` 재정렬 제거** → generateCandidates 의 휴리스틱
  순서를 그대로 씀(어차피 UCT 가 값 정렬). **트리/확장 비용 6~7배↓**(depth-0 sims=800 중반
  11s→1.7s). 프로파일로 이게 비-롤아웃 비용의 대부분임을 확인.
- 튜닝 파라미터 노출: `mctsRolloutDepth`·`mctsEpsilon`·`mctsRolloutWidth`(롤아웃 greedy 가
  evaluate 할 후보 상한 — 비용 대부분이 evaluate×후보수). 기본값은 기존 강한 설정 유지(depth=5,
  width=64) — 커밋된 동작 무변(no regression).
- `tests/ai-mcts.test.ts`: 빠른 설정(예방=depth0 sims2000, 공격=depth0 sims1000, 합법=depth2)으로
  교체 → CI **22s→2.1s**. 예방은 트리+solver 가 만들어 롤아웃 없이도 됨을 확인.

### 결정 사항 / 측정
- **프로파일**: 롤아웃이 잔여 비용 ~95%. 롤아웃 step 비용 대부분 = `evaluate×후보(~15)`(~90 보드
  스캔) ≫ generateCandidates(~10). 그래서 rolloutWidth(평가 후보 상한)가 핵심 레버.
- **Pareto(측정)**: ▸ **빠름** depth=0 sims=2000(~1s)·depth=2 width=6 sims=800(~1~5s) → vs expert
  **4-4(비등)** + 게임1 회랑 **예방 O**. ▸ **강함** depth=5 full sims=800 → **15-3** 이지만 ~16~31s.
  롤아웃을 줄이면 dominance 가 빠지고 비등으로 수렴(rollout 의 정확한 lookahead 가 강함의 원천).
- **예방의 출처는 롤아웃이 아니라 트리+solver**: depth=0(롤아웃 0)도 게임1을 예방한다(회랑 라인을
  끝까지 탐색→확정 패배 역전파). 그래서 빠른 설정도 예방을 유지한다.
- **막다른 길(되돌림)**: 룰 기반 가벼운 롤아웃(`rolloutPolicy:'lines'`, evaluate 없이 런 연장/차단)을
  넣어 봤다. 빠르지만(~3s) **값이 오도(誤導)** 돼(런만 늘리고 회랑은 안 봄) 트리 선택을 회랑에서
  멀어지게 함 → **예방 X**. 코드 제거. 교훈: 가벼운 롤아웃 정책은 값이 게임 전략을 반영해야 한다.

### 미해결 / 다음 할 일
- **fast-MCTS(≈expert+예방+~1s)가 UI 후보**: expert 보다 후반(2~30s)이 더 빠르고 회랑을 막으니
  실전 체감은 개선. 단 일반 강도는 비등이라 "더 강한 AI"는 아님 → 노출 시 자리매김 주의.
- "빠르고 dominant"는 학습 가치함수(AlphaZero-lite)나 훨씬 똑똑한 경량 롤아웃이 있어야 — 큰 작업.
- 기본값을 fast 로 바꿀지(usable) vs strong 유지(15-3 정체성)는 UI 노출과 함께 결정.
