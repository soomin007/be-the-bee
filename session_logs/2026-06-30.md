## 복기 분석 정확도↑ (hard + negamax 깊은 평가) — backlog #3 ②

### 요약
사용자 선택으로 실수 분석 정확도를 높였다. 점수 계산을 medium **1수 정적 평가** → **hard + negamax
깊은 평가**(상대 응수까지 반영)로 바꿨다. 분석이 무거워질 수 있어 진입이 아니라 "이 판 분석"을
펼칠 때 1회만 계산하도록 조정.

### 주요 변경
- `src/engine/ai.ts`: `scoreAfterMove(state, move, player, cfg, depth)` 신설 — 한 수를 둔 뒤 player
  관점의 깊은 평가(`negamax` 로 상대 응수까지). `analyzeGame` 의 점수 계산을 1수 `evaluate` →
  `scoreAfterMove` 로 교체, 기본 cfg `medium` → **`hard`**(depth-4). 점수 손해 = (최선 수 깊은 평가
  − 실제 수 깊은 평가)/100. ai.ts 내부라 `negamax`(비공개) 직접 재사용.
- `src/ui/game-ui.ts`: 분석 캐싱 시점을 **복기 진입 → "이 판 분석" 펼칠 때**로 이동. 안 펼치면 계산
  0(진입이 무거운 hard 탐색에 안 막힘), 펼치면 1회 계산 후 캐싱(슬라이더/재생 재계산 없음).

### 결정 사항
- **왜 1수 평가 → negamax**: 1수 정적 평가는 "상대가 바로 응징하는 수"의 손해를 못 본다. negamax 로
  둔 뒤 상대 최선 응수까지 보면 점수 손해가 정확해진다(추천 수도 hard 로 더 정확).
- **왜 펼칠 때 계산**: hard 탐색은 실수 여러 개·후반 국면에서 무거울 수 있다. 분석은 사용자가 📊 를
  눌러 명시 요청할 때만 필요하므로, 그때 1회 계산하면 진입은 항상 가볍다. (무거우면 Worker 는 후속.)

### 검증
- check:engine·typecheck·build·106 테스트. missBlock 추천 차단 수·점수 손해>0 유지(hard negamax,
  단일 32ms). 브라우저: 분석 펼침(hard 경로) 무크래시(에러 0).

### 미해결 / 다음 할 일

- 실수 아닌 모든 수 점수 손해는 여전히 후속(노이즈·성능 검토 필요).

모든 수를 가벼운 1수 평가로 훑고, 손해가 큰 수만 hard 정밀 분석한다(2단계). backlog #3 완결.

### 주요 변경
- `src/engine/ai.ts`: `MoveNote` 에 `inaccuracy` 추가(notePolarity=bad). `quick1plyLoss`(1수 손해,
  빠름) 신설. `analyzeGame` 점수 로직을 2단계로 — 모든 수를 quick 으로 훑어 손해가 `ANALYZE_QUICK_RAW`

  inaccuracy 로 리스트에 추가. blunder 는 기존대로 추천·손해 부착.
- `src/ui/game-ui.ts`: `NOTE_TEXT.inaccuracy = '더 나은 수가 있었어요.'`.
- `tests/review.test.ts`: 약한 수(4목 연장 놓침)가 inaccuracy 로 잡히는지 검증 추가(추천·손해>0).

### 결정 사항
- **2단계(quick→hard)인 이유**: 모든 수 hard 는 너무 느리다(80수면 수십초). 1수 평가로 싸게 훑어
  "볼 가치 있는 수"만 hard 정밀 → 정확도(hard)와 속도(대부분 quick) 양립. 35수 분석 ~860ms(워커).
- **보수적 임계**(QUICK 6000·INACCURACY 9000): 작은 손해는 이 게임 평가(휴리스틱)에선 노이즈라
  제외. 고수 대국(실전 35수)은 inaccuracy 0개, 약한 수는 잡힘 — 의도대로 "눈에 띄는 아쉬움"만.
