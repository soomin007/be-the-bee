# 2026-09-15 세션 로그

## 요약
GitHub 에서 "Supabase keep-alive 워크플로가 곧 비활성화됩니다" 메일. 공개 레포에 60일간 커밋이 없으면
schedule 트리거가 꺼지는 규칙이고(마지막 커밋 07-24, 53일째), 꺼지면 Supabase 일시정지 → 온라인 대전만
죽는 연쇄다. 워크플로가 매 실행마다 자기 자신을 API 로 강제 enable 해 카운터를 리셋하도록 고쳤다.

## 주요 변경
- `.github/workflows/supabase-keepalive.yml`: `permissions: actions: write` + 첫 스텝
  `gh api -X PUT repos/<레포>/actions/workflows/supabase-keepalive.yml/enable`. 틀린 가정 주석 정정.
- `.github/workflows/deploy.yml`: push 때마다 keep-alive 를 다시 켜는 `revive-keepalive` 잡(자가 복구).
- `docs/design/known_issues.md`: 2026-09-15 항목(증상·원인·재발 방지).

## 결정 사항
- 레퍼런스 조사: 해법은 ① 더미 커밋 자동 생성(efrecon/gh-action-keepalive 등) ② 강제 enable API 로
  카운터 리셋(liskin/gh-workflow-keepalive, PhrozenByte/gh-workflow-immortality). 히스토리를 더럽히지 않는
  ②를 택했고, 액션의 실체가 gh 한 줄이라 서드파티 의존 없이 직접 넣었다. 기본 GITHUB_TOKEN 이면 된다
  (PAT 불필요, 같은 레포라서). 메일의 "workflows page 에서 방지" 버튼과 같은 동작.
- 검증: 로컬 gh 로 엔드포인트 204 확인 → push 후 workflow_dispatch 실행에서 새 첫 스텝 통과,
  deploy 의 revive-keepalive 잡 success. 오늘 push 자체로 60일 카운터도 이미 리셋됨.
- 기존 keepalive 액션 대표 레포(gautamkrishnar/keepalive-workflow)는 GitHub 이 ToS 위반으로 내린 상태라
  참고 불가. 이런 이유로도 서드파티 액션 의존은 피하는 편이 낫다.
